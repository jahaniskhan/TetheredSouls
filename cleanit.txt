## 1. Block Model
`Block.swift` defines the core game element used for gameplay.

### Key Properties
- `id: UUID` - Unique identifier for each block instance
- `shape: [[Bool]]` - 2D array representing the block's shape (true = filled cell, false = empty)
- `color: BlockColor` - The color of the block (enum with predefined colors from Theme)
- `rotationStates: [[[Bool]]]` - Precomputed rotations of the block (0°, 90°, 180°, 270°)
- `symbol: String` - String identifier for the block, used for accessibility and debugging

### Initialization
```swift
init(shape: [[Bool]], color: BlockColor, symbol: String, id: UUID = UUID())
```
- Creates a new block with the specified shape, color, and symbol
- Automatically computes rotational variants (0°, 90°, 180°, 270°)
- Always generates a unique ID when not explicitly provided
- Uses static rotation helper to ensure initialization completes properly

### Static Methods
```swift
static func rotateMatrix(_ matrix: [[Bool]]) -> [[Bool]]
```
- Rotates a shape matrix 90 degrees clockwise
- Used internally during initialization
- Must be static to avoid using partially initialized `self` during initialization

```swift
static func createRandom() -> Block
```
- Creates a random block by selecting one from predefined templates
- Ensures each instance has a unique ID
- Used by ContentView for generating initial blocks and replacements

### Static Properties
```swift
static let blocks: [Block]
```
- Array of predefined block templates used throughout the game
- Source for random block generation and replacement

## 2. BlockView Component
`BlockView.swift` provides a simple visual representation of a block.

### Key Properties
- `block: Block` - The block to display

### Rendering Logic
- Iterates through the block's shape matrix
- Renders filled cells as rounded rectangles with the block's color
- Uses a standard cell size of 30x30 points
- Arranges cells in a grid pattern matching the block's shape

### Usage Scenarios
- Used primarily for static display of blocks
- Rendered with proper alignment based on block shape dimensions
- Simplifies the visualization of different block types in various contexts
- Doesn't have interactive capabilities (those are in DraggableBlock)

## 3. DraggableBlock Component
`DraggableBlock.swift` handles the interactive dragging of blocks.

### Key Properties
- `selectedBlock: Binding<Block?>` - Currently selected block
- `isDragging: Binding<Bool>` - Tracks whether a drag operation is in progress
- `blockPosition: Binding<CGPoint?>` - Current position of the dragged block
- `grid: Binding<[[Bool]]>` - Game grid state
- `projectedCells: Binding<[(row: Int, column: Int)]>` - Grid cells the block would occupy
- `gridGeometry: GridGeometry` - Information about grid dimensions and cell sizes

### Gesture System Integration
- Works with `GestureMode` system to determine when dragging is permitted
- Integrates with DirectCatEyeControl to coordinate cat eye animations
- Posts notifications for cross-component communication during drag operations
- Maintains internal state for gesture management

### Drag Gesture Handling
- Uses global coordinate space for consistent positioning
- Tracks drag start and current position
- Updates cat eye animations based on drag position (via DirectCatEyeControl)
- Posts notifications to coordinate with other components
- Throttles updates to maintain performance

### Grid Projection
```swift
private func calculateGridProjection(at position: CGPoint)
```
- Determines which grid cells the block would occupy at the current position
- Updates shared projection coordinator
- Filters out invalid cells that are outside grid bounds
- Used for visual feedback when dragging over the grid

### Drag End Handling
```swift
private func handleDragEnded(at position: CGPoint)
```
- Attempts to place the block on the grid
- Animates block placement
- Coordinates state transitions
- Sends notifications to update cat animations and game state
- Triggers haptic feedback on successful placement

### Drag Cancellation
```swift
private func handleDragCancelled()
```
- Handles forced cancellation of an ongoing drag
- Resets all relevant state variables
- Clears grid projection
- Updates cat eye position and state
- Used for emergency recovery when gesture states become inconsistent

## 4. BlockPreview Component
`BlockPreview.swift` renders preview versions of blocks in selection UI.

### Key Properties
- `block: Block` - Block to preview
- `gridGeometry: GridGeometry` - Information about grid dimensions
- `isSelected: Bool` - Whether this block is currently selected
- `scale: CGFloat` - Size scaling factor
- `cellSize: CGFloat?` - Optional override for cell size
- `namespace: Namespace.ID` - For matched geometry effect animations

### Rendering Approach
- Uses GeometryReader to adapt to available space
- Renders block cells with the block's shape and color
- Supports dynamic sizing based on container dimensions
- Integrates with matched geometry effects for smooth transitions

### Block Dimensions Calculation
```swift
private var blockDimensions: (rows: Int, cols: Int)
```
- Computes the dimensions of the block from its shape matrix
- Used to determine the appropriate size for the preview

### Cell Size Calculation
```swift
private func getCellSize(_ geometry: GeometryProxy, rows: Int, cols: Int) -> CGFloat
```
- Calculates appropriate cell size based on available space and block dimensions
- Respects the optional cellSize parameter if provided
- Otherwise dynamically sizes to fit within available space

### Animation Support
- Provides matchedGeometryEffect integration for smooth animations
- Supports rotation animation via rotationEffect
- Implements scaling and opacity changes for interactive feedback

## 5. DoodleType System
`DoodleType.swift` defines different decorative elements that appear during gameplay.

### Enum Cases
- `star`, `heart`, `semicolon`, `moon`, `swirl`, `xSmile`, `sparkle`, `twentyEight`

### Key Properties
- `systemName: String` - System icon name when applicable
- `rotationRange: ClosedRange<Double>` - Valid rotation angles for the doodle
- `animationSpeed: Double` - Speed multiplier for animations
- `movementAmplitude: Double` - Size of movement in animations

### Animation Parameters
- Each doodle type has specific animation behaviors tuned for performance and visual appeal
- Special handling for symbolic types like `twentyEight` and `semicolon`
- Variable animation speeds to create visual diversity

### Static Methods
```swift
static func getWeightedType(index: Int) -> DoodleType
```
- Returns a doodle type with weighted probability
- Makes certain types (like twentyEight and semicolon) appear more frequently
- Uses modulo operations to create a deterministic but varied selection pattern
- Helps ensure consistent distribution of doodle types for visual harmony

## 6. DoodleElement Component

### Key Properties

- `color: Color` - Randomly chosen from a vibrant palette

### Rendering Logic
- Uses a type-specific view builder to render each doodle type
- Applies rotation and stop-motion effects
- Implements subtle animations for certain doodle types
- Optimizes rendering based on doodle type

### Animation System
- Implements stop-motion effects for specific doodle types
- Uses uniqueId to generate deterministic but varied animations
- Employs delayed animation sequences for performant visual variety
- Special handling for twentyEight and semicolon doodles

### Doodle Type Implementations
- Each doodle type has a dedicated struct (StarDoodle, HeartDoodle, etc.)
- Implementations focus on performance with simple Text or path-based rendering
- Custom drawing for complex shapes like XSmileDoodle
- Optimized shadow and effect usage to maintain performance

### Performance Considerations
- Uses simple text-based rendering whenever possible
- Applies shadows selectively to maintain performance
- Leverages hash-based randomization for deterministic behaviors
- Minimizes state changes and animations for frequently updated doodles

## 8. Game Interaction Modes
The game supports two distinct interaction modes controlled via the `GestureMode` enum.

### Mode Types
- `blockDragging` - For grid and block interactions
- `catInteraction` - For cat eye and heart gestures

### Mode Management
```swift
static var current: GestureMode = .blockDragging
```
- Global static property tracks the current active mode
- Components check this property to determine behavior
- Notifications broadcast mode changes across components

### Mode Switching
```swift
private func toggleGestureMode()
```
- ContentView provides controls for switching between modes
- Forces reset of any ongoing drag operations during mode change
- Updates global state and broadcasts changes via notifications
- Adjusts UI elements to reflect the current mode

### Component Integration
- DraggableBlock enables/disables gestures based on mode
- BlockSelectionView adapts UI elements to current mode
- Cat animations and interactions adjust to match current mode
- Grid projection only occurs in blockDragging mode

## 11. Component Interactions
The TetheredSouls game relies on complex interactions between components to create a cohesive experience.

### Block Selection Flow
1. User selects a block from `BlockSelectionView`
2. Selection triggers `BlockPreview` to render the selected block
3. When dragging begins, `DraggableBlock` takes over rendering
4. Grid projection shows where the block would be placed
5. On successful placement, block is added to the grid and score is updated

### Cat Animation Coordination
1. `DraggableBlock` updates DirectCatEyeControl during dragging
2. Eye positions update based on drag position
3. Notifications inform cat component about drag state changes
4. Cat responds to block placement with animations
5. Position reset occurs after drag completes

### Doodle Animation System
1. Score changes trigger doodle position updates
2. DoodlePositionManager unlocks positions briefly
3. Hash-based calculations create deterministic animations
4. Position updates use batching for performance
5. Dragging temporarily pauses animations

### Gesture Mode Switching
1. User toggles between blockDragging and catInteraction modes
2. ContentView updates global GestureMode.current
3. Notifications inform all components about mode change
4. Components enable/disable gestures accordingly
5. Visual indicators update to reflect the current mode

### Notification System
- ForceCatEyeFrame - Updates cat eye position
- BlockDragging/BlockDraggingEnded - Signals drag state changes
- GestureModeChanged - Broadcasts mode switches
- ForceDragReset/DragStateReset/FinalDragReset - Emergency reset sequence
- GameDraggingStateChanged - Informs animation systems about drag state

## 12. Performance Optimizations
The TetheredSouls implementation includes several key optimizations for smooth performance.

### Doodle Rendering
- Uses Text-based rendering instead of complex paths when possible
- Implements batch updates to limit the number of animations
- Employs throttling to prevent excessive recalculations
- Pauses animations during dragging operations

### Position Management
- Locks positions most of the time to prevent unnecessary recalculations
- Uses hash-based deterministic positions instead of random values
- Caches position data to minimize geometry calculations
- Implements selective animation to limit CPU usage

### Animation Techniques
- Simplifies animations during high-activity moments
- Uses deterministic animations based on IDs
- Implements stop-motion effect for specific doodle types
- Controls animation speed and timing to reduce CPU load

### Drag Performance
- Uses throttled updates for position calculations
- Implements controlled animation sequences to prevent conflicts
- Optimizes notification flow to reduce redundant updates
- Uses direct control methods for critical animations

### State Management
- Implements careful reset sequences to avoid state conflicts
- Uses delayed execution for animation synchronization
- Provides multiple fallback mechanisms for error recovery
- Separates visual updates from state changes for smoother animations

## 13. State Management Patterns
The TetheredSouls application implements several patterns to manage complex state.

### Single Source of Truth
- GameStateManager serves as the central state store
- ContentView coordinates high-level state changes
- Bindings pass state to child components
- State dependencies are clearly defined

### Binding Propagation
- Core state variables use @Binding for two-way communication
- Computed bindings transform state for specific needs
- Component-specific state uses @State for isolation
- Updates are coordinated through a binding hierarchy

### Notification-Based Coordination
- Cross-component updates use NotificationCenter
- Critical state changes broadcast notifications
- Components observe relevant notifications
- Emergency resets trigger notification sequences

### Stateful Singletons
- DoodlePositionManager tracks animation state
- GridProjectionCoordinator manages grid overlays
- DirectCatEyeControl manages eye animations
- GameStateManager maintains core game state

### Reset Mechanisms
- Multi-stage reset process ensures clean state
- Timeout detection prevents stuck states
- Emergency override bypasses normal state flow
- Visual indicators show state for debugging
